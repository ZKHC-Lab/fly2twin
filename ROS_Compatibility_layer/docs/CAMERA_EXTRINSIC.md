# 机体→相机外参（body → camera_color_optical_frame）

2026-10-23 · Claude

S380 上 FAST-LIO 机体系 `body` 到 RealSense 彩色光学系 `camera_color_optical_frame` 的静态外参原先有误：平移沿相机光轴偏了约 27 cm，旋转偏了约 1.2°。本文记录新值、怎么定出来的、验证数字，以及对在线和离线链路的影响。原始材料都在本地，只在文末证据索引中列出。

## 1. 新旧外参

| | 平移 xyz（m，body 系） | 四元数 xyzw | 来源 |
|---|---|---|---|
| 原值（2026-09 至 2026-10-22） | 0.329365 / 0.033964 / −0.079647 | 0.502057 / −0.498710 / 0.500910 / −0.498314 | 硬件组 FAST-LIVO2 `Rcl/Pcl` 取逆，并假设 `body == lidar` |
| **新值（2026-10-23 起）** | **0.056558 / −0.006717 / −0.077751** | **−0.494176 / 0.506142 / −0.498990 / 0.500618** | D435i 深度与局部雷达的 6 自由度配准，三次录制合并（第 3 节） |

- 新值下相机光心在机体原点前方约 5.7 cm、下方约 7.8 cm。原值是前方 33 cm，超过 S380 半个轴距（19 cm）。
- 原值错在平移，旋转基本正确。“`body` 是雷达系转 25° 安装俯仰，所以要补 25°”这一假设已经检验过，会带来 25° 的旋转差，不成立。

外参数值不在任何 yaml 里，只写在两处，常数相同：NX 台架由 `nx_step2_bringup.sh` 发布，bag 回放由 `tools/bag/replay_worker.py` 发布。G4 从快照记录的 `/tf_static` 条目读取外参。发布命令：

```bash
rosrun tf2_ros static_transform_publisher \
  0.056558 -0.006717 -0.077751 -0.494176 0.506142 -0.498990 0.500618 \
  body camera_color_optical_frame
```

## 2. 怎么发现的

1. **点云对不上雷达：** 视觉点云与雷达比对时，D435i 深度点也有 75% 在 10 cm 内找不到雷达点。比对用的是该帧前后 ±0.5 s 的雷达扫描，已去畸变，并去掉了机身和持机人。
2. **单轴扫描：** 只把相机沿光轴后移 0.275 m，在未参与选参的 68 帧上，无参照比例从 75% 降到 12%，带符号偏差从 3.0 cm 降到 0.3 cm。同一检验里，扫深度尺度和时间偏移的改善都小得多。
3. **视觉 BA 的独立证据（不用雷达）：** 图像 BA 求出的相机中心减去 LIO 推出的相机中心，在相机系里三次录制都沿光轴偏负，横向和竖向接近 0。
   - office_gs_02：−17.2 cm；ctrl_wall_01：−11.7 cm；office_gs_03：−18.3 cm。
   - BA 带 σ 5 cm 的 LIO 位置先验，会把结果往回拉，所以真实偏差更大。

## 3. 估计：两种互不依赖、也不受 BA 先验牵制的方法

| 方法 | 录制 | 修正量 Δt，相机系 xyz（m） | 修正旋转向量（°） |
|---|---|---|---|
| D435i ↔ 局部雷达，点到平面配准 | office_gs_01 | 0.040 / −0.006 / −0.289 | — |
| 同上 | office_gs_02 | 0.041 / 0.001 / −0.275 | — |
| 同上 | ctrl_wall_01 | 0.040 / 0.002 / −0.270 | — |
| 同上 | **三次合并（采用）** | **0.041 / −0.001 / −0.273** | 0.05 / 0.63 / 1.12 |
| 纯图像 SfM 与 LIO 相对运动手眼标定（AX = XB） | 三次合并 | 0.020 / −0.035 / −0.293 | 0.23 / 0.86 / 1.09 |

- 配准方法的三次录制之间，光轴方向只差 2 cm。
- 手眼标定用的是 office_gs_02、ctrl_wall_01、office_gs_03，是另一组录制和另一种原理，结果与配准相差约 4 cm。
- 配准方法在三次录制上都有 D435i，且在按时间分块的留出帧上检验，所以采用它。

| 同上：LIO 位姿 + SIFT/XFeat 先验 BA | — | 4.4 / 25.9 → 4.0 / 17.0 | — | 3.9 / 21.1 → 3.2 / 11.4 |

整层点云的比较条件：
- 同一录制的四份点云用同一份 VGGT-Omega 512 深度，逐帧尺度分别拟合各自版本的 BA 点；
- 融合规则相同，距离是每个融合点到清理后雷达地图的最近邻；
- 没有对任何一份点云做雷达 ICP 或 Sim(3)。
- 新外参下重扫时间偏移，两次录制的最优值仍为 +40 ms。

整层点云的 P90 在两次录制上都降到约一半，即大尺度的双层墙已经消除。30 cm 面片内偏离自身主平面 3–15 cm 的点的占比没有下降：office_gs_02 为 50.3% → 50.7%，office_gs_03 为 51.5% → 53.1%。这个指标只覆盖 15 cm 以内的局部厚度，外参造成的错位通常更大。剩下的局部厚度可能来自深度噪声和逐帧尺度，这一点还没有验证。

3DGS 测试时对齐后的 PSNR，均为单种子：

| 录制与设置 | 插值帧 | 留出段 |
|---|---|---|
| office_gs_02：连续留出切分（507 训练帧），SIFT + XFeat 先验 BA、各向异性正则、30000 步 | 24.75 → 25.43 dB | 17.17 → 17.13 dB |
| office_gs_03：1588 训练帧，同样的 BA 和正则，94000 步 | 22.23 → 23.41 dB | 18.27 → 19.95 dB |

office_gs_03 留出段低于 15 dB 的帧从 14 帧降到 4 帧（共 132 帧）。新视角仍受采集覆盖限制。

## 5. 影响

- **在线链路（G4 `frame_pose`）：** 每帧深度直接用“LIO 位姿 × 外参”放进地图。光轴方向 27 cm 的平移误差会随朝向变化：同一面墙从相反方向看时，会被放到相距最多约半米的两处。这是在线点云重影的一个直接来源。
- **离线链路：** BA 吸收了大部分误差，但 LIO 位置先验仍按错误外参算，BA 被拉向错误位置。修正后，BA 与 LIO 的偏离从 15–19 cm 降到 3.5–6.5 cm。
- **以前的诊断要重新理解：**
  - “LIO 相机位姿帧间约 1°、对极误差 2.3 px”，有一部分来自这个外参，这一点已经由修正后对极误差下降印证；
  - “BA 与 LIO 中心相差约 20 cm”，主要来自这个外参；
  - ctrl_wall_01 的最佳时间偏移从 +20 ms 变为 +40 ms（与其他录制一致），原来的差异也是外参造成的。

## 6. 使用要求

- **NX：** `nx_step2_bringup.sh` 发布新值。`tf_ok` 按 `tf_echo` 输出的新值（平移 [0.057, −0.007, −0.078]）判定；旧发布者仍在运行时脚本会报错，要先停掉再重跑。
- **旧 bag：** 2026-10-23 之前录的 bag，`/tf_static` 里存的是原值。`tools/bag` 回放不播放 bag 里的 `/tf_static`，自己发布新值。其他离线处理也要用新值覆盖，不能直接读 bag 里的外参。
- **硬件：** 硬件组需要核对原 0.329 m 的推导：`Rcl/Pcl` 所在坐标系，以及 `body == lidar` 这一假设。之后如果做带标定板的正式标定，以正式结果为准，并用本文第 4 节的指标复核。

## 7. 已验证与未验证

已验证：
- 第 3、4 节的数字。
- 场景为同一办公室的 office_gs_01、office_gs_02、office_gs_03，以及受控墙面 ctrl_wall_01，都是手持录制。
- 时间偏移固定为各录制已标定值；office_gs_02、office_gs_03 在新值下重扫，最优值不变。

未验证：
- 正式标定板标定；
- 飞行状态下的振动与机架形变；
- 新值下在线 G4 的点云质量；
- 新值下的其余离线基线：除第 4 节两次录制的点云和 3DGS 外，其余 3DGS 实验数字是原外参下的结果；
- 局部厚度（面片指标）没有随外参下降的原因；
- 修改版 FAST-LIO 的 `install_pitch_deg 25` 发布约定（只做过几何自检，源码未核）。
