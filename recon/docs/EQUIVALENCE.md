### E0 实测补充

固定相机留出 16.768221 dB、插值 24.960747 dB；对齐口径为原 T30 的 200 步相机拟合，不含手机颜色拟合。30,000 步训练 1,747.109 s，最终 1,505,402 高斯，训练帧访问 59–60 次。初始化 280,798 点，2 cm 点数 2,244,232，最终体素 0.05223113795557858 m，窗口尺度最大差 0，均与原 T30 完全相同。峰值 GPU allocated/reserved 为 2.247/3.797 GiB，CPU RSS 2.839 GiB。逐帧指标重新聚合与摘要一致。高斯数不逐位相同，E0 的两个对齐 PSNR 判据通过，没有改容差。

### E1 实测补充

使用原 T31 P-MIX 相机与 T17 Omega512 窗口、原模糊掩码定义的全部 670 清晰帧。2 cm 融合点数 2,732,886，最终 848,586 点；不仅计数和体素相同，全部初始化 XYZ/RGB 与窗口尺度也逐元素相同。固定原始归一化三字段，精化相机先转 float32 再归一化。40,200 步训练 2,666.649 s，每帧精确访问 60 次。最终高斯数 1,555,189；在所有训练帧固定 BA 位姿下分别计算 PSNR 后平均为 26.4789622189 dB。峰值 GPU allocated/reserved 为 2.333/3.729 GiB，CPU RSS 4.129 GiB。GPU 训练不是逐位一致，但高斯数和 PSNR 均在原定容差内。

### E2 中间阶段与模型兼容

视频重新解码 2,590 帧，选中 1,200 帧；源帧号与原 cameras.npz 逐元素相同，所选清晰度中位数 278.45716056283084 也与原 extract.json 相同。首次读取 shared 失败：前序清理误将 COLMAP 的 frames.bin 当成抽帧缓存删除，留下孤立 rigs.bin，pycolmap4.2.0 因而报 unordered_node_map 键缺失；不是原始 SfM 数据本来缺失。此次执行只将新仓副本的孤立 rigs.bin 改名保留，以完整的 cameras/images/points3D 三件套按 legacy 格式读入并恢复 trivial rigs，得到 1,200 帧、466,299 点、1 共享相机，没有重估 SfM。原项目负责人随后已修复全部 71 个受影响模型目录，复核相机、位姿、二维点数、三维点坐标/颜色及轨迹长度，不一致项为 0，原 rigs 另存备份。本次继续使用已独立恢复的本地副本，后续仍检查去畸变内参、相机、稀疏点及原报告归一化，不能以成功读取代替等价验收。

确定性预检实测：center=`[-0.18381673303773566, 0.17757476362912664, 0.2799049712131365]`，P95=`5.7505289037468525`，与原 metrics 存储值最大绝对差均为 0；没有剔除相机，训练/测试 1050/150。1920×1080 去畸变内参为 `fx=1427.5660009667213, fy=1427.5694166460796, cx=959.994755398873, cy=539.9983419409392`，所有 K 与 c2w 逐元素相同。稀疏点读回顺序与原内存导出顺序不同；466,299 条 XYZ+RGB 按六列联合排序后逐元素相同，最大差 0。保留实际读回顺序训练，并将此差异与 GPU 非确定性一起作为训练不逐位相同的已知因素，不用它放宽验收容差。

### E2 训练与评测

63,000 步训练 5,387.583 s，每个训练帧精确访问 60 次。最终 1,602,977 高斯，相对 1,582,100 为 +1.319575%；1600×900 的 150 个固定位姿测试视角平均 PSNR 32.7823182678 dB，相对 32.77 为 +0.012318 dB，两项通过。GPU allocated/reserved 峰值 2.430/3.648 GiB，CPU RSS 1.733 GiB；本次采用 32 帧 LRU 图像缓存，没有任何深度缓存或深度渲染。

### E3 从视频端到端

从 fix 原视频重新抽帧（1200 帧，帧号与原 extract.json 逐个相同），新建特征库与 GLOMAP 全局建图，不复用原 SfM、图像或缓存。特征提取 321 s、匹配 699 s、回环对 600 个，SfM 全程 3,645 s；注册 1200/1200，只有一个模型。GLOMAP 有随机性，相机与原模型不逐元素相同，因此训练/测试划分沿用同一规则（index%8==7）而不是原帧集合的位姿。63,000 步训练 3,243.552 s，每个训练帧访问 60 次，最终 1,559,138 高斯；GPU allocated/reserved 峰值 2.368/3.492 GiB，CPU RSS 5.798 GiB（1,200 帧图像缓存）。

## 抽离与兼容决策

同一个 [训练器](../gaussian/train.py)支持两条参考。[无人机预设](../../configs/drone_with_poses.yaml)指定精确 N×60、1280×720、固定致密化时间表、SH 间隔 1000、正整数倍 reset、1M 初始化上限及全部清晰帧。历史 E2/E3 手机 RGB-only 设置已内联到[验收脚本](../../scripts/equivalence.py)，保留精确 N×60、宽 1600、缩放并 round 的致密化时间表、SH 间隔 steps/30、第零步 reset、RGB 与各向异性损失。[当前手机预设](../../configs/phone_video.yaml)改为 B0，加入无人机方法的 Omega 深度、米制融合和 λ=0.1 深度损失；不将上文 E2/E3 数字当作 B0 分阶段版本的验收。已有 T30 的默认值不变。

| 阶段 | 复用代码 | 保留与差异 |
| --- | --- | --- |
| 抽帧 | [extract_frames](../video/extract_frames.py) | 原始清晰度分箱、HDR 识别、ffmpeg 滤镜、JPEG 编码、源帧号；拒绝覆盖已有抽帧目录，不删除旧数据 |
| SfM/去畸变 | [sfm](../video/sfm.py) | 原序列 overlap20/quadratic、600 回环对、GLOMAP、共享相机及 OpenCV alpha0 不裁切；完整注册率单独验收，不因保留最大模型就宣称成功 |

| 手机适配 | [pipeline](../video/pipeline.py) | 先 float32 相机再归一化；K 直接按比例缩放，不改成无人机半像素公式；图像从全栈改为 32 帧 LRU，OpenCV 像素计算不变 |
| 训练顺序 | [schedule](../gaussian/schedule.py)、[strategy](../gaussian/strategy.py) | 手机参考循环前额外生成一次 permutation，作为显式配置保留；zero-depth 不访问深度缓存也不请求深度渲染 |

| 漫游 | [render_roam](../video/render_roam.py)、[prepare_route](../video/prepare_route.py) | 原平滑、Catmull-Rom、SLERP 与覆盖检查；0.12 归一化单位/8° 至少 95%，策划路径另验地面高度跨度 0.15。地面 ROI 与帧段仍是参考场景专用，不能当通用地面估计 |

| 查看器 | 场景适配（来源仓库 viewer/src/scene-contract.js，本次未搬入）、资产准备（来源仓库 viewer/tools/prepare_web.py，本次未搬入） | 线上代码读 scene.json，不再硬编码 scenes.json；真实非对称内参投影与留边；默认采集走廊约束；无占用体素时不宣称具备重建表面碰撞 |

### 环境差异必须保留

无人机参考为本地检出版 gsplat 1.5.3，手机参考为环境 1.5.2。独立仓库目前使用公开 1.5.3 的数值原语及显式 callback 复现这两种 reset 语义。版本相同不等于实现逐位一致；GPU 容差验收没有完成前不作质量等价结论。AST 比较已确认 1.5.2/独立安装 1.5.3 的 DefaultStrategy 状态累计、grow/prune、前向 callback、初始化与所有 ops 函数相同，仅 post-backward callback 不同；这不证明 CUDA rasterizer 逐位相同。

查看器默认用代码内置的四旋翼几何体表示无人机；研发仓库里旧的演示无人机 GLB 原始资产再分发许可未确认，不随开源仓库导出。没有复制毕设控制或 GPL 仿真代码。

## 运行入口

- 原回归：`CUDA_VISIBLE_DEVICES='' python -m pytest -q tests`。
- 手机 B0 正式入口：`recon run --config my_phone.yaml --through prepare` → `--through fuse` → `--only train` → `--only eval` → `--only export`，用当前手机预设填写视频与权重路径。位姿 provider/refine、相高假设与 CPU 验收见[输入契约](INPUTS.md)。
- 历史 E2/E3 顺序工具仍为 `python -m recon.video.extract_frames` → `python -m recon.video.sfm` → `python -m recon.video.pipeline` → `python -m recon.video.export`，RGB-only 设置由验收脚本独立保存。
- 本地严格验收：[equivalence.py](../../scripts/equivalence.py) 接收显式 reference/config/video/output，不导入研究脚本。
- 查看器入口：index.html（来源仓库 viewer/index.html，本次未搬入），查询参数 `manifest` 指定导出 scene.json URL。多档资产脚本接收 `--scene`，生成 scene-web.json，原始 scene.json 不覆盖。
- 有头浏览器验收：verify_scene.cjs（来源仓库 viewer/tools/verify_scene.cjs，本次未搬入），依赖可通过 `npm install --prefix viewer/tools` 安装。参数依次为仓库根、scene.json 绝对路径、结果 JSON；使用本机 Edge（可由 `CHROME` 指定），不强制软件或独显后端。
- GPU 步骤均须外层 `flock <共享锁> <命令>`；重任务外层 `systemd-run --user --scope -q -p MemoryMax=16G`。产物在忽略的 outputs 下，不进入 Git。
